# RQ2 Experiment Add-on (2026-11-23)

An **offline, non-destructive add-on** for the existing `hj-editable-token-mappings` code-completion-lab research branch. It implements case preparation for the proposed RQ2 design, a reproducible four-condition summary table, retrieval Top-1/3/5/10/20 coverage, and evaluation figures. It does **not** modify existing legacy runner scripts. No API calls are made by either tool.

## Offline RQ2 case preparation

**Small Basic** (mapped cases already generated by the existing README pipeline):

```bash
python3 tools/prepare_rq2_cases.py \
  --input results/sb-full/cases_mapped.jsonl \
  --output results/rq2/sb-lab-full/cases.jsonl \
  --profile lab --ideal-repetitions 3
```

**C** (one prepared file from `run_hj_c_batch.py`; source paths vary):

```bash
python3 tools/prepare_rq2_cases.py \
  --input results/c-full-infill-v1/files/<file-name>/cases.jsonl \
  --output results/rq2/c-lab-last10/cases.jsonl \
  --profile lab --c-context last10 --ideal-repetitions 3
```

For a reproduction-oriented prompt rather than the lab wording, use `--profile monir-style`. This **does not assert exact source parity** with the Monir archived API messages; it still needs golden prompt fixtures. C also accepts `--c-context full`. Prefix-only is the default. This tool intentionally refuses `--c-completion infill`, which needs verified suffix handling through a separate dedicated pipeline.

### IMPORTANT: generation engine change still needed

The generated cases contain five condition templates and an explicit `repetitions` field:

- `without_guidance` → 3 requests
- `guided_rank_1` → 1 request
- `guided_rank_2` → 1 request
- `guided_rank_3` → 1 request
- `ideal_guidance` → **3 requests** (or 1 when overridden for a pilot)

Therefore each complete strict RQ2 case costs **9 requests** by default, not 6. `oracle_reference_structure=true` explicitly flags the leakage permitted *only for ideal guidance*. The new `cases.jsonl` is a **preparation artifact**; do not give it to a legacy generator until that generator has been extended and tested to honor the new condition and repetitions, including its resume task IDs and score labels. The old main experiment must remain available unchanged.

The ideal condition is only included for cases with exactly one verified reference and at least three candidates. This may differ from the eligible cohort in older experiments. Always publish number of cases and exclusions. The reference **structure** enters ideal prompt deliberately; the reference **text** must never enter any prefix-only prompt.

## Reconstruct Monir-style RQ2 table from existing scores

Small Basic current (without ideal still produces three available arms and blank ideal):

```bash
python3 tools/rq2_report.py \
  --cases 'results/sb-full/cases_mapped.jsonl' \
  --retrieval-cases 'results/sb-full/prepared.jsonl' \
  --scores 'results/sb-full/grok_scores.csv' \
  --out results/rq2/reports/sb-grok --plots
```

C (all file scores for one provider):

```bash
python3 tools/rq2_report.py \
  --cases 'results/c-full-infill-v1/files/*/cases.jsonl' \
  --retrieval-cases 'results/c-full-infill-v1/files/*/prepared.jsonl' \
  --scores 'results/c-full-infill-v1/files/*/grok_scores.csv' \
  --out results/rq2/reports/c-grok --plots
```

Once new ideal scores exist, add their CSV file patterns to `--scores`. They must use the **same model, case IDs, language, prompt profile, and completion context** as the other arms. Do not mix C prefix-only new results with older C FIM scores. Different model temperature/output-budget runs must also be kept in separate reports.

If there are overlapping original and new score CSV rows, the report refuses duplicated `(case_id, model, condition, repetition)` keys instead of silently double counting them.

### Created outputs

- `rq2_by_case.csv` — one row per cursor/model/metric with the four arms and missingness status.
- `rq2_table.csv` — one row per language/model/metric/condition and aggregation.
- `retrieval_coverage.csv` — Top-1/3/5/10/20 structural reference coverage, with explicit denominators.
- `figures/*.png` and `*.svg` — four-arm score charts, Monir-style win/tie/loss-vs-candidate-count charts, and retrieval coverage (with `--plots`).

**Aggregation modes** in `rq2_table.csv`:

- `micro_cursor`: average over eligible cursor positions for that arm.
- `macro_file`: average within each file, then average equally across source files (closer to the Monir reported scheme).
- `paired_micro`: average only over positions that have all four arms; it is blank until ideal scores are present. **Use this for controlled comparisons.**

For each metric `WithinTop3Guide` takes the maximum of guided Rank 1/2/3 at that position. This is an **oracle upper bound**, not a deployable rank selector. As implemented here, the maximum is calculated **separately for each metric**: the best BLEU prediction and the best SequenceMatcher prediction may be different candidates. Publish that policy explicitly.

### SacreBLEU nomenclature

The current score CSV has both `sacrebleu_sentence_13a` (full sentence BLEU, 0–100) and `sacrebleu_unigram_precision` (1-gram precision, 0–100). Monir's figure/table uses **precision of the first SacreBLEU n-gram order**. Use the unigram precision column for *conceptual* comparison, but verify exact tokenizer, library version, zero-length handling and aggregation to claim numerical equivalence. `sequence_matcher_raw` is a 0–1 ratio converted to percentage in the reports.

### Top-K strategy

`retrieval_coverage.csv` needs **no API requests**; it uses `retrieval_rank` from the HJ prepared cases. There is no guarantee that reference structures are always within Top-20. Query the actual coverage before spending money. Top-10/20 **generation** should be a smaller, preregistered stratified ablation after the Top-3 main study, rather than increasing all cursors to 20 calls.

### Verification status

Both tools and their synthetic unit tests run successfully in the current environment. No real HJ binary was executed and no commercial LLM API was called here. Full integration into the existing language entrypoints and generation engines remains **unverified**, especially `ideal_guidance` repetition/resume, C 10-line prompts, and cross-run parity. Do not label this add-on production-ready or merge it onto main without a WSL smoke test and golden prompt tests.
